# 已实现：知行三层记忆与个性化规划设计

日期：2026-11-20。状态：已按本次实现请求完成三层记忆及管理入口。文件名保留以兼容原链接；功能代码、幂等 SQL、配置与页面已同步，未修改简历和面试包。验证为真实 PostgreSQL/Redis 配合替身模型，不代表真实模型效果。实现入口与验证见 [04：三层记忆与偏好规划](../learning/04-三层记忆与偏好规划.md)。

## 1. 核心新功能

**让知行在长对话里保留重要信息，并在新会话中记住用户认可的出行偏好。**

一次完成以下三层，不分期交付：

| 层次 | 作用 | 旅行例子 | 存储 |
| --- | --- | --- | --- |
| 近期对话记忆 | 保留近期原话，理解指代和追问 | “第二个酒店换一下” | 现有 Redis 角色消息窗口 |
| 会话摘要记忆 | 压缩同会话较早的重要信息，延长对话记忆 | 聊了很多轮后，仍记得这次带老人、尽量少走路 | PostgreSQL，会话级摘要 |
| 长期偏好记忆 | 跨会话沿用用户明确认可的习惯 | 新建行程也知道用户偏好高铁、不吃辣 | PostgreSQL，用户级档案 |

会话摘要服务于当前会话，长期偏好服务于同一用户的不同会话。本次明确要求始终优先。

同时完成自然语言记住/忘记、简单偏好管理面板和原有增量重规划适配。采用现有框架与中间件，不增加独立记忆服务、复杂画像、候选审批流程或历史行程向量库。

## 2. 用户实际能做什么

1. **连续追问：**刚看完酒店建议，说“第二个太远，换一个”，系统理解指代，只更新住宿相关内容。
2. **长对话：**较早说“这次带老人，不想走太多路”，后来讨论很多轮交通和餐饮，仍能通过摘要和当前需求保留有效条件。
3. **跨会话沿用：**说“以后推荐餐厅尽量不辣，帮我记住”，保存后新建旅行会话也能默认参考。
4. **本次例外：**说“这次想尝试辣菜”，只覆盖当前行程，不永久修改长期“不辣”。
5. **修改和忘记：**自然语言明确要求更新/忘记，或在“我的旅行偏好”面板编辑、清空。

用户明确要求保存时直接保存并回执，不再增加一次候选审批；普通的“这次不辣”只作用于本次。含义或类别不明确时先问清楚，不自动猜测。

## 3. 三层分别怎样实现

### 近期对话

- 沿用角色、会话隔离的消息窗口，规划角色以最多 20 条消息为可配置起点。工具调用与工具返回按框架规则配对处理，不截断成非法消息序列。
- Redis 消息记忆使用独立过期配置，默认 7 天，不把连接超时当作保存期限。角色窗口缺失时，从 SQL 回填有效范围内的近期已完成业务消息，排除本轮未回答的问题；通过 NX 和 TTL 避免覆盖新窗口及重复回源。不恢复没有持久化的工具轨迹。
- 消息条数不等于 Token 预算，长消息、工具结果及检索片段还需限制输入长度。独立普通对话测试接口不在本次调整范围。

### 会话摘要

- 从本会话已保存的业务对话中总结，不复制工具日志、整份攻略或大段历史方案。
- 近期原话保留约 10 轮业务对话；窗口外尚未摘要的老消息达到 10 条时，调用一次摘要模型，每次最多处理 40 条连续老消息，摘要控制在约 600 字以内。阈值均可配置。
- 使用“旧摘要 + 尚未覆盖的老消息 → 新摘要”，记录已覆盖范围，避免漏过消息、重复压缩和每次重读全部历史。覆盖位置使用服务端明确选定的消息范围，不用随机 UUID 推断时间顺序。
- 按本次背景、交通、住宿、美食组织摘要，只给各角色注入相关部分；区分用户明确条件、已讨论建议和待确认事项。
- 本次 State 和最新纠正优先。改了目的地后，摘要不能继续把旧目的地写成当前事实；生成摘要时提供当前结构化需求作核对依据。
- 摘要失败时，不推进覆盖范围；正常规划继续使用同版本旧摘要、近期消息和 State，后续请求再尝试，不增加后台队列。
- 摘要输入设置长度上限，过长消息分段处理，只有实际处理完成的范围才标记已覆盖。每轮最多增加一次摘要调用，不为每个角色分别总结。

### 长期偏好

- 只做交通、住宿、美食三类，每类一段可编辑文本，建议最多 300 字。例如优先高铁、住宿安静、口味清淡。
- 用户明确说“记住”“以后默认”“长期改成”，或在面板保存，才写长期档案；明确要求忘记时删除并反馈结果。
- 偏好提取复用原有需求分析调用，不每轮增加单独的提取模型。模型只返回类别、内容及操作，身份和字段校验由后端负责。
- 只能依据用户当前输入，不能从助手推荐、攻略和工具返回推断用户习惯。修改时回执该类别的完整新内容，用户可直接在面板纠正。
- 不自动长期保存具体日期、目的地、人数，不做复杂语义合并、健康画像或预算画像。

## 4. 三层怎样参与原有规划

```text
本轮用户输入
  → 认证、会话归属校验，沿用会话锁
  → 读取当前 State、长期偏好、摘要与近期消息
  → 需求分析：本次增量 + 是否明确记住/忘记
       ├─ 只管理记忆：处理并回复，不启动旅行规划
       └─ 正常规划：合并有效需求，决定执行或复用哪些分支
            → 当前需求 + 默认偏好 + 相关摘要 + 近期消息 + 私人攻略
            → 交通 / 住宿 / 美食 Agent → 汇总与保存
  → 达到阈值时更新摘要；摘要失败不阻断正常规划
```

保留用户本次的原始需求，另外计算实际交给 Agent 的有效需求，不能把长期默认值写成用户本次明确说过的条件。

每类偏好只需区分：继承长期默认值、本次明确覆盖、本次不使用历史偏好。采用类别整体覆盖，不把可能冲突的两段文本自动拼接；用户可直接指定本次完整条件。

本次全局约束、明确要求和最新纠正优先于长期默认值与摘要。私人攻略是参考数据，不改变指令优先级，也不自动形成长期记忆。

| 变化 | 处理 |
| --- | --- |
| 只改本次美食偏好 | 重跑美食，复用交通与住宿 |
| 长期美食偏好变化，本次正在继承 | 后续规划请求重算美食 |
| 长期美食偏好变化，本次已有明确覆盖 | 有效输入没变，不额外重跑 |
| 修改目的地 | 沿用原规则重跑全部 |
| 只有摘要更新，需求和有效偏好未变 | 不因此重跑全部分支 |
| 只保存或删除长期偏好 | 不自动改写已展示方案，后续规划按新偏好执行 |

分支记录实际输入指纹，按有效变化决定结果能否复用。现有资料版本规则继续保留。旧检查点里的显式偏好仍作为本次条件，不反向写入长期档案。

## 5. 存储和管理保持简单

优先复用现有 [store 表](../../database/01-init.sql) 保存两类 JSON 记录，不新增独立数据库或记忆服务：

| 记录 | 范围 | 主要内容 |
| --- | --- | --- |
| 用户偏好档案 | userId | 三类偏好、版本、更新时间、最近操作标识 |
| 会话摘要 | userId + sessionId | 分类摘要、覆盖范围、上下文版本、更新时间 |

近期角色消息继续存 Redis，原始业务聊天继续存 message 表。摘要不替代历史记录，删除长期偏好也不等于删除过去的聊天。

旧 user.preferences 文本不自动视为已确认的结构化偏好，不自动迁移或猜测。

页面新增一个“我的旅行偏好”面板：三个输入区，支持保存、清空某类和删除全部。对话中简短提示已记住、已忘记或本次参考了哪些偏好，不显示内部版本和存储键。

提供读取与更新本人偏好的接口，页面和自然语言调用同一后端服务。更新使用期望版本和操作标识，防止并发覆盖与重复提交，不另建候选审批状态机。

## 6. 必须处理的几个边界

**防止旧偏好复活：**删除或修改长期偏好后，切换相关消息上下文，更新或清除旧摘要，从当前明确 State 和新版本下的对话重新建立摘要；不能把变更前的所有原话重新压回去。用户另外明确指定过的本次条件与长期默认值要区分，不能因为删长期档案就擅自删除本次条件。

**保持原有私人 RAG 可用：**当前 [RagContentRetriever.retrieve](../../src/main/java/cn/zhixing/travel/rag/RagContentRetriever.java) 用 chatMemoryId 查原会话。增加记忆版本时要同步适配，保留可验证的原 sessionId；不能拿新的 Redis 版本键直接查会话。图 threadId 继续表示原会话，消息记忆可以换范围，检索器仍核验真实归属。

**隔离与并发：**userId 来自认证入口，访问摘要仍检查会话归属；同会话沿用单实例锁，不同会话更新同一档案靠数据库版本和短事务，不在模型调用期间持有档案行锁。上下文显式传递，不依赖异步线程的 ThreadLocal。

**失败反馈：**写入失败不能回复已记住；摘要失败不推进覆盖范围；读取长期档案失败要说明本次未应用个性化。规划期间相关有效偏好变化时，旧结果不能作为最新有效方案复用，提示重新规划，不自动无限重试。

**输出类型：**纯记忆操作不能触发日期追问，也不能覆盖 latest_plan，需要判断本轮是否真正生成了完成方案，不能仅凭 missing=false 保存。

## 自查解答

1. 近期原话支持指代和追问，摘要保留同会话较早的重要信息，长期偏好跨会话提供用户认可的默认条件。
2. 摘要提供压缩语义背景，检查点保存结构化状态和执行位置；两者不能替代。
3. 本次明确要求优先，只影响本次，不自动永久修改档案。
4. 旧摘要、窗口和已合并的默认值都可能继续携带旧偏好，必须切换上下文并重新判断有效输入；本次独立明确的条件仍保留。
5. 未拆分，近期窗口、摘要、长期偏好及管理入口已一起实现，真实模型效果仍待联调。
